# AU22 implementation evidence

## Scope

The Admin Accounts directory now projects the full website-account total and
disabled count alongside the filtered, paged rows. Counts remain accurate when
search or role filters are active, disabled website accounts stay visible, and
page input is clamped before calculating the database offset so an extreme
positive value cannot overflow. The Danish resource contains the new summary
label; the neutral resource continues to use the source English format string.

Manage now consumes a generated reset result into a request-scoped
`CredentialLink` only when its target account and `reset` purpose match. A
mismatched or stale TempData result is removed before rendering, so a response
for account A cannot display its secret on account B. The raw link remains
transient and is never included in the account projection, URL, history, audit,
or persistent client state. Existing reset generation and F4 consume-time
authorization remain unchanged.

The Accounts overlay captures each manage request identity, ignores late
responses after the route context changes, and prevents directory navigation
while a manage action is pending. This preserves current-state readback without
attributing a later matching state to the earlier request.
