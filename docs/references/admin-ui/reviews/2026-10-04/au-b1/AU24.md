# AU24 implementation evidence

## Scope

Ownership transfer now requires the selected active website account's public
username confirmation in addition to the current owner's password. The form
still carries the selected destination ID and rendered authorization version;
the page submits the typed username through a new typed-ID service overload and
never calls the legacy username-only overload. The service rechecks the actor,
destination, destination authorization version, active eligibility, password,
and normalized typed username under the existing ordered row locks before
changing roles. Empty and mismatched confirmations fail without changing roles
or writing transfer audit rows. The existing atomic two-role transfer,
single-owner invariant, reset-token supersession, audit records, and session
invalidation remain unchanged.
