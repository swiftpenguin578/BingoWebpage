### Required WOM reference corrections

**W1 — P2: unavailable/revoked credentials and deletion eligibility are misrepresented.** `Wom.dc.html:610,846–848,872–888`. `canWrite` treats every website-created link and an external `unavailable` code as writable. A website-created rejected/unavailable code can still expose Delete; revoked code falls through to “Not added.” Production `EventCompetitionManagement.cs:99–102` allows only Valid/Unverified, and deletion also requires eligible protected credentials (`EventCompetitionManagementService:368–377`). Consequence: the page promises updates/deletion that the service refuses and supplies the wrong recovery. Smallest correction: separate provenance from server CanWrite/CanDelete and model revoked/unavailable explicitly; offer credential recovery without claiming updates are enabled or changing origin.

**W2 — P2: navigation/reload abandons pending work and delivers its result to another event.** `Wom.dc.html:577–602,630–644,654–664,687–691,754–756`. Event switching and Reload have no busy guard; dialog busy only protects close/back while that dialog exists. Start Fetch on A, switch to B: mutation is captured against A, but completion `refreshView` and success time read `this.srv()` for B. A code/link result can similarly close a later dialog and focus unrelated controls. Smallest correction: preserve a captured event/operation identity, guard in-page navigation while pending, and ignore/route stale completions correctly. Carry unresolved state across allowed genuine navigation instead of silently abandoning it. Restore focus only in the active matching context.

**W3 — P2: fetch readback treats any old success as this fetch finishing.** `Wom.dc.html:641,738–746`. Uncertainty retains only kind/slug, and any `lastOk` produces “The fetch finished,” even if it is the pre-request cache. No read-error branch exists. Smallest correction: retain baseline source/generation/last-success/attempt identity; describe current authoritative data, and only claim a new success when proven. A nonmatching current state cannot prove “No new data was saved”; preserve uncertainty on read failure and never re-fetch as readback. The fixed timeout fixture currently always saves; that does not make the recovery predicate valid.

**W4 — P2: edited dialog values are discarded without the required choice.** `Wom.dc.html:584,588–592,750–755,917–926`. Back, Escape, backdrop, Cancel and reload clear a typed replacement ID/code or disconnect reason. Smallest correction: apply the existing dirty-close policy to unsent drafts; Cancel of the discard prompt retains them. The secret must still clear immediately on send and never enter URL/history/toasts. This is not permission to retain a submitted secret for recovery.

**W5 — P2: unknown update can coexist with “Up to date.”** `Wom.dc.html:816,868–873`. An update with status unknown gets an uncertainty banner, but misses queued/conflict/delete branches and falls through to “Up to date” from `lastUpdate`. Consequence: unconfirmed current synchronization is represented as confirmed. Smallest correction: render unknown update as unresolved with the last *confirmed* update separately, and project failed/reconciliation-required state rather than falling through to success. Same message selection should avoid a stale-data banner alongside the unresolved-fetch notice (`179–185,827`).

**W6 — P2: modal omits background scroll locking.** `Wom.dc.html:951` locks only mobile navigation, not the active dialog. Shared scroller remains scrollable. Smallest correction: include the dialog in the existing lock condition, retaining trap/Cancel entry focus/animated close. No visual pass claimed.
