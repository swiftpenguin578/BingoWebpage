### Board reference corrections

**B1 — P1: uncertain tile saves can report success when nothing was saved, and discard the only entered values.** `Board.dc.html:987`, `1005–1013`, `1167–1169`. Uncertain settle closes/removes the editor. Existing-tile verification compares only objectives; a name/description/artwork/EHB-only edit with `timeoutNot` has unchanged objectives and therefore produces “is saved.” New-tile verification accepts any tile at the intended position. Conversely, a mismatch becomes “Nothing changed, so it’s safe to try again,” which authoritative current state alone cannot prove. Correction publication and discard both verify only `!correction` (1235/1243), so the opposite action also qualifies as success. Smallest correction: retain the immutable intended payload and recoverable editor draft; use complete intended state/identity to describe what is currently present, without attributing request success or promising safe replay. Preserve unresolved/read-failed states. If request-specific proof is desired, separately define the minimal backend receipt/readback contract. Do not copy this mock's boolean verifier into production.

**B2 — P2: takeover bypasses unsaved-change protection and can overwrite a later edit.** `Board.dc.html:906`, `1105`, `1148–1165`, `1319–1326`, `1025–1029`. `protoTakeover` retains the draft but marks the drawer read-only; `edDirty` then returns false. Close/Escape/navigation discards actual unsaved values without the required discard choice. After takeover back, the old draft becomes editable with no retained expected version comparison in `saveEd`; another admin's intervening tile edit is overwritten. Smallest correction: measure dirty state independently of current edit permission, retain the opening baseline/version through takeover and refresh, and require explicit stale reconciliation before saving. Preserve production BoardVersion/lease checks. Correct the takeover dialog's “anything ... is lost” copy (`1667`) to agree with retained drafts. This is a recovery correction, not automatic merging authority.

**B3 — P1: correction simulation does not preserve evidence arriving after the snapshot/private edit.** `Board.dc.html:1230–1233`, `1242`, `1338–1342`; compare production `Board.cshtml.cs:1031–1044` and FUNCTIONAL_CONTRACTS 6.2. Publishing a correction checks completeness/rates/GP only; it never compares current evidence-bound rules to the active published rules. An admin may save an unevidenced objective change, then use “evidence arrives,” then publish the altered rules. Discard replaces tiles with their frozen `evidence` arrays, losing evidence locks added since freeze; starting another correction then permits changing/removing that tile. Smallest correction: keep evidence identity/locks separate from restored board design, and recheck late evidence against the published snapshot before replacement. Rejected publication must preserve the active snapshot. These are already required protections, not new scope decisions.

**B4 — P2: an unknown direct Board route crashes instead of presenting unavailable/recovery.** `Board.dc.html:830–832`, `888–901`, `946–956`. Any syntactically valid slug is accepted and `load` calls `clone(this.ev())`; an unknown slug yields undefined and JSON parsing fails. Smallest correction: validate the selected event before constructing the snapshot and show a safe not-found/unavailable state with an Events route. Do not silently pick another event. Real hidden/missing/unauthorized events must use existing server visibility gates.

**B5 — P2: simulated Forward/Back leaves a tile URL without its drawer, and initial direct entry cannot close through Back.** `Board.dc.html:898–901`, `926–927`, `1096`, `1106–1109`. Open a tile, use the Board navigation link to return to the same event’s base Board URL (which pushes that URL), then Back: `applyEntry` clears `ed`, detects same-event pop, and skips `load(r.tile)`, leaving `?tile=` without an editor. At an initial direct tile entry, `hist.idx === 0` short-circuits before `popLayer`, so Back does not close the drawer despite the stated layer-first behavior. Smallest correction: restore tile state on same-page history transitions and process open layers before history-boundary checks. Keep dirty protection and focus restoration in that route path. No objection to the deliberate in-memory browser simulation itself.

**B6 — P2: EHB input accepts a value it then calculates differently.** `Board.dc.html:685–690`, `1114`, `1130–1132`. Validation replaces a comma before `parseFloat`, but stored draft/calculation retains the original string; `1,5` validates as 1.5 and displays/freezes 1. `1abc` is also accepted as 1. Smallest correction: use one complete decimal parser/normalization path for validation, stored intended value, calculation and readback; reject trailing junk. Reuse application decimal bounds.

**B7 — P2: local EHB formula misrepresents supported weighted objectives; planning duration also changes without approval.** `Board.dc.html:658–661` uses target divided by expected weighted rate, unlike production `EhbCalculator.cs:27–50`'s remaining-progress outcome calculation. It also lowers the distinct-item bound to 12 (666) versus production 20 (7). This is a concrete behavior difference beyond fixture values. Smallest correction: use faithful calculator results/fixtures or explicitly identify simplified figures and remove false validation limits; production integration must reuse EhbCalculator. Separately `stats` clamps event length to one day (859), while production `Board.cshtml.cs:1607` uses 0.5; a 12-hour event's per-player/day estimate halves. Preserve existing duration semantics unless separately approved.

Additional source qualification, not a demonstrated fixture regression: Board grid/line/planning values use `tileCalc` on working data (`849–860`,1460–1466) in all modes while only preview uses frozen values (`1646`). Integration must select the immutable approval/publication projection already provided by production.
